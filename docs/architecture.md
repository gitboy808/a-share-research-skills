# A 股投研 skill 套件设计

状态：已实施，当前工作区 schema 为 `a-share-workspace-v3`；工作集装配、可重建投影和隔离迁移由 ADR-0012–0028 约束。

本设计定义可组合 skill、证据包、机会扫描、动态策略画像、分级自治和阶段化上下文。领域术语以根目录 `CONTEXT.md` 为准，架构取舍以 `docs/adr/0005` 至 `0028` 为准。

## 1. 目标与非目标

目标：把机会发现、事实核实、方向判断、双轴复盘和周期学习拆成可独立调用、可组合、可审计的工作流；同时降低追高、错误归因和错误离场，并提高低热度启动方向的发现提前量。

当前非目标：无人值守调度、数据库主事实源、自动买卖、仓位指令、以不可观察的“主力意图”作为事实、为了兼容旧 `fenxi` 而保留旧规则。

## 2. 套件结构

根目录：`.agents/skills/a-share/`

```text
a-share/
├── a-share-research/       # 统一入口与复合编排
├── a-share-scan/           # 宽范围机会扫描
├── a-share-investigate/    # 事实调研与证据包
├── a-share-analyze/        # 方向逻辑与原子判断
├── a-share-review/         # 结果轴 + 过程轴复盘
├── a-share-meta-review/    # 经验、校准与策略版本演进
└── shared/
    ├── context/            # 深模块：assemble / hydrate 与内部实现
    ├── contracts/          # 版本化任务契约
    ├── schemas/             # 当前 schema
    └── scripts/             # 校验、ID 与紧凑 JSON CLI
```

每个目录包含独立 `SKILL.md` 和 `agents/openai.yaml`。专用 skill 可直接调用；默认入口为 `a-share-research`。套件根目录不是可触发 skill。

## 3. 路由

| 用户意图 | 默认工作流 |
|---|---|
| 看看、研究一下、了解一下 | 调研，不生成判断 |
| 核实、梳理资料、业务或产业链关系 | 调研 |
| 分析、上涨逻辑、持续性、给跟踪指标 | 调研 → 分析 |
| 扫描低位、轮动、补涨、低热度潜力 | 扫描 |
| 盘前 | 扫描刷新 → 调研 → 盘前分析 |
| 竞价、盘中、事件影响 | 增量调研 → 对应阶段分析 |
| 复盘、验证旧判断 | 复盘 |
| 元复盘、周度收敛、策略优化 | 元复盘 |
| 先复盘再前瞻 | 复盘冻结 → 新快照调研 → 新分析 |

盘中大盘或轮动分析自动加入增量扫描；复盘发现拥挤方向衰减后可追加扫描。单一对象请求只检查直接替代或轮动关系，不默认全市场扫描。当前所有流程仍由用户触发。

## 4. 公共执行规则

1. 入口生成运行清单和阶段快照；专用 skill 复用。直接调用时专用 skill 自行预检并输出开工简报。
2. 工作区、schema、输入版本或写入目标不可验证时停止写入。
3. 产生持久写入时保存 `RUN-YYYYMMDD-NNN`；只读任务不落盘。复合任务共享 RUN ID，但各阶段分别冻结快照。
4. 核心 schema 强制，叙事章节按需。缺失项显式写为未知或证据缺口。
5. 历史事实、证据包、判断和复盘只追加，不回写。
6. 文档是唯一事实源；共享脚本只校验 schema、ID、引用、版本链和派生索引，不形成投研结论或无痕修复内容。
7. 工作流只消费 `shared/context` 的装配结果，不直接读取 SQLite、FTS5、字段权威映射或语义 adapter。
8. 来源载荷只通过外置 store 保存和定位；工作集清单及 CLI 不回传完整载荷。

## 5. 工作流契约

### 5.1 统一入口

核心字段：意图与路由置信度、对象、阶段、周期、持仓上下文、工作区健康、开工简报、工作流顺序、快照边界、产物 ID、组合摘要、未知与降级原因。入口只编排，不创造新的事实或判断格式。

### 5.2 机会扫描

核心字段：扫描时点与覆盖率、市场状态与轮动阶段、拥挤方向衰减、低热度分位与变化、相对强度、内部广度、成交承接、催化接近度、轮动映射、候选策略画像、半衰期、确认、失效、最大价格位移、到期、调研优先级、候选版本变化与后续评价字段。

扫描使用热度—确认矩阵：低热度且早期确认增强者优先；低热度但无确认者仅低优先观察；高热度且价格接受者可能延续但必须过价格纪律门；高热度且不被接受者优先视为兑现或退潮风险。

观察候选使用 `CYYYYMMDD-NNN`，写入 `观察池.md` 与 `观察日志/YYYY-MM.md`。观察池最多 20 个，候选不输出涨跌置信度、不进入判断日志。触发后仍须调研与分析。

扫描评价同时衡量有效发现率、发现提前量、误报率和漏检率。方向后来上涨但发现或触发时已越过价格纪律门，不算成功。

### 5.3 事实调研

核心字段：任务与对象、信息截止时间和各市场交易日、上次证据包与档案版本、差量、原子证据、来源链、冲突与否证、关键缺口、字段时效、档案事实更新、新证据包 ID、完整/部分/不可取得的完成度。

证据包按月归档，使用唯一 ID，可关联多个对象。每个原子证据项只含一个可核验事实，分别记录确认状态、来源独立性、事件与发布时间、数据口径、适用交易日、关联字段与过期条件。事实、叙事与推测严格分区。

复杂调研可按外围、产业政策、公司事实、行情结构和反方证据并行；subagent 只返回候选材料，主 agent 单点核验、去重、统一口径和落盘。

### 5.4 判断分析

核心字段：分析阶段、截止时间、证据包版本、历史差量、市场状态与门槛、外围映射、产业/主题状态、定价主导模式、估值锚、策略画像和版本、行情主驱动与次驱动、预计半衰期、消息定价链、上涨与下跌逻辑、唯一基准情景、研究状态、原子判断、判断链、跟踪指标、可选持仓纪律和未知项。

分析只消费通过任务完整性检查的证据包。完全没有证据包时返回不落盘的 `investigation_required` 流程阻断；已有证据包但关键证据不足时，先把控制权交还路由器显式调用调研刷新，未刷新或无法补齐才引用原包形成可计分弃权。两者都不得无痕搜索。分析阶段取盘前、竞价、盘中、突发事件或非交易时段专题；盘后验证不属于分析。

价格纪律门独立于方向逻辑，检查价格偏离、确认窗口、证伪距离、潜在空间、拥挤与承接。方向逻辑成立但赔率消失时必须等待或规避，价格纪律不得提高方向置信度。

### 5.5 双轴复盘

核心字段：触发类型、原判断及版本、原快照、证据包与策略版本、实际开高低收和相对表现、确认与证伪触发顺序、结果状态、过程状态、弃权反事实、主要与次要错误、驱动/定价/画像识别评价、追高或错误离场检查、证据簇、教训支持或反例、当前判断状态、需刷新事实项。

到期必须复盘；到期前只允许在预设证伪、官方否证或数据污染时提前结案。普通观点变化由分析追加版本。复盘只追加每日证据，不升级市场教训或参数。

结果证伪但过程合规、单样本无法识别具体缺陷时，错误归因可记“不适用—合规概率损失”，只进入累计概率校准，不为每次证伪强造市场教训。旧 schema 按当时规则审计，缺少后来新增字段只标记审计范围受限，不自动判为失真。

### 5.6 元复盘

核心字段：周期与截止时间、按结果/过程/置信/周期/市场状态/驱动/画像分层统计、重复错误、弃权质量、教训生命周期、正式与影子同快照对比、L2 生成/晋级/回滚、L3 提案、信源和数据事故、常驻层维护、下一周期预注册实验、未解决项。

预注册实验固定适用范围、主指标、保护指标、样本定义和停止条件，不得看到结果后更换。

### 5.7 工作集装配与阶段交接

工作集装配 module 的公共 interface 只有：

- `assemble(运行清单, 任务证据清单)`：返回唯一的 `stable_references` 集合、覆盖、缺口、投影状态、语义降级和软预算质量指标。
- `hydrate(稳定引用集合)`：按哈希校验重新定位原子研究单元和有界核验原文；无法定位或内容变化时返回核验失败，不使用陈旧文本。

任务证据清单由 `shared/contracts/` 的版本化任务契约实例化。语义候选和软预算只能增加候选或优化重复视图，不能删除必需项、抵消否决/冲突/过期证据或改变研究状态。

资格选择完全封装在该 module 内，按 requirement 编译并随 stable reference 保存：`prospective_current` 只给扫描、调研和分析提供 cutoff 时仍有效的当前原子；`historical_as_of` 用于复盘的原判断、原证据和后来结果三条独立时间边界；`calibration_window` 给元复盘读取窗口内已终止样本。hydrate 必须重新解析 Markdown 并重验资格、cutoff、显式替代和内容哈希。被排除原子只写入 audit-only reference，不默认 hydrate；完整语义见 `shared/context/README.md` 和 ADR-0029。

判断的当前有效状态由原快照及追加的结果、时限、失效和终止记录派生，不能让 `研究状态` 冒充最终状态。对象档案按字段原子建立 current view；字段使用稳定 logical identity、独立版本、最后核实、有效期、状态、来源与 supersedes，文件级 active 不能覆盖字段过期。多版本事实只有显式同一 logical identity 时才互斥，文件日期不构成替代。

阶段之间只传递运行清单、任务证据清单、正式产物 ID、稳定引用和工作集清单；网页回传、终端输出、来源载荷正文和临时推理在阶段结束时从活跃上下文释放。被正式证据稳定引用的外置 payload 与 sidecar 不随上下文释放而删除，至少保留至引用失效并完成复核。

## 6. 定价、驱动与策略画像

分析先确定一个主驱动和最多一个不得单独提高置信度的次驱动。驱动类型取结构趋势、资金轮动、事件情绪、超跌修复或混合/未知，并绑定确认、证伪与半衰期。

定价主导模式取基本面、情绪、混合或未知。基本面模式使用适配公司经济结构的估值锚；情绪模式短周期提高情绪权重，但估值仍是退潮后的尾部风险参照。消息必须依次检查事实、预期差、计价程度和价格接受。

策略画像由一个基础画像与最多一个限时战术修饰组成：

- 基础画像：周期型、稳定价值型、高成长兑现型、资产重估型、困境反转型或未知。
- 战术修饰：政策驱动、事件驱动、情绪加速、超跌修复、低流动性风险或无。

情绪使用热度、扩散、拥挤、价格接受、衰减五维向量；其权重和阈值由策略画像决定。网络热度不能脱离价格与资金确认提高置信度。

轮动映射必须说明资金竞争、风险偏好、产业替代、政策资源或指数再平衡机制，并记录市场状态、资金环境、时滞与证据簇。只有短期负相关时只能列候选假设。

## 7. 策略库与自治

策略库使用“版本化 Markdown + YAML 元数据 + 当前索引”。每个版本声明范围、激活与失效、最大周期、证据角色、参数和范围、支持教训、证据簇、晋级状态及回滚条件。

证据先分为否决项、主证据、确认项和背景项；只在同一角色内使用数值权重或动态阈值，否决项不能被综合分抵消。首批策略使用试运行状态，未校准数值标记为设计先验；只有当结论依赖该参数时才限制为低置信。

自治等级：

- L0：统计、证据簇、档案时效等机械记录，自动执行。
- L1：按既定样本门槛升级、限制或退役市场教训，自动执行。
- L2：获授权参数的版本化调整。结构参数慢验证，情境参数可按场景即时激活和自动失效。
- L3：风险原则、证据底线、输出边界、错误分类、skill 架构与字段权限，只能提案并等待用户确认。

结构参数默认最低验证线为 10 个独立证据簇、2 种市场状态和 4 个自然周。候选先作为影子版本并行运行，依次比较过程完整性、风险错误、概率校准、判断质量和机会效率，满足门槛后自动晋级，触发风险条件时自动回滚。

情境参数服务轮动、题材和超跌修复等短周期场景，可以即时调整情景权重、确认窗口、追高约束和跟踪阈值，但不得降低证据底线；首次新情境最高低置信，未经慢验证不得推广为结构参数。

## 8. 写入所有权

| 工作流 | 可以写入 | 禁止写入 |
|---|---|---|
| 入口 | 运行记录、组合报告 | 证据、判断、经验和参数事实源 |
| 扫描 | 观察候选、扫描报告 | 正式证据、判断、经验和参数 |
| 调研 | 证据包、档案事实字段、调研报告 | 判断结果、教训状态和参数 |
| 分析 | 判断日志、当前判断、档案分析字段、分析报告 | 回写证据、评分旧判断和升级经验 |
| 复盘 | 结果轴、过程轴、错误、证据簇、移除已结案当前判断 | 改写原判断、升级教训和调参 |
| 元复盘 | 教训状态、策略版本、校准统计、周收敛 | 改写历史证据和判断快照 |

官方否证或数据污染通过追加暂停记录处理，不构成回写例外。

## 9. 投影、来源与审计产物

- 文档事实源由 `shared/context` 重建 `a-share-context-projection-v1` SQLite 数据库和 FTS5 词法索引；数据库不纳入事实源，也不接受模型直接写入。
- 装配前比较事实文档内容哈希和投影 schema。陈旧或损坏时先全量重建，重建失败则禁用陈旧结果并直读相关 Markdown，同时标记 `projection_degraded`。
- Augment 只实现可替换语义 adapter；未安装、未配置或异常时，本地结构化覆盖、FTS5 和事实源直读仍完整工作。
- 来源载荷外置在阶段 store，原子单元只保存来源身份、哈希和定位；`hydrate` 才取得有界核验片段。
- 持久任务在运行记录旁保存 JSON 工作集清单，包含 live stable references、编译资格策略、audit-only references、受控关系/选择原因、契约版本、覆盖缺口、投影和上下文质量，不复制正文。无法继续作为 live 支撑证据的迁移旧引用只能保存为 `historically_referenced_evidence` 审计关系；它不展开依赖、不 hydrate 目标、不计覆盖，也不制造缺失依赖阻断，但必须保留可回查的旧引用与迁移映射。
- 状态解析对复合文本保持风险优先：包含“冲突/否证/否决”标记的状态不计为已覆盖并标记否决角色；“已确认 + 未证实”混合状态不被整体静默降级，必须拆分原子事实或由任务显式处理。

## 10. 工作区产物

- 现有：`CONTEXT.md`、`研究规则.md`、`经验库.md`、`当前判断.md`、判断日志、对象档案、报告、周收敛。
- 新增：`观察池.md`、观察日志、证据包、策略库、运行记录。
- 模板：工作区 `模板/` 是唯一模板源，新增运行清单、工作集清单、扫描报告、观察候选、调研报告、证据包和策略版本模板，并升级现有模板。
- 校验：套件共享只读校验脚本；允许从事实文档重建派生索引，不允许无痕修改事实。

## 11. 历史迁移与影子验收

默认 `validate_release.py` 使用 `live` profile，只验证当前 v3 在线运行面；`--profile full` 额外验证 migrate、shadow replay、对应 schema 与验收文档组成的 compatibility kit。两者共享事实 schema，但 compatibility 工具不属于默认 live parser 或发布面。

`scripts/migrate_workspace.py` 只接受隔离的 `--input` 与 `--output`。它把历史报告目录归并到 `报告/`，将证据包、策略、运行记录以及判断日志、对象档案、报告、周收敛和观察日志的历史容器补齐为当前 schema 元数据，保存旧/新路径、迁移前后哈希和缺失字段清单，并把无法证明的新增字段写成“当时未记录”。正文保持原样，输出不保留旧目录或 legacy runtime parser；输入目录始终只读。

迁移报告的 `status=completed` 只表示结构复制与重写完成，`acceptance.status` 在影子回放前保持 `not_run`；必需项召回、否决/冲突/否证/过期遗漏和上下文代理指标由隔离副本回放清单单独报告，不能由迁移工具自行宣称通过。

迁移后必须在隔离副本回放代表性扫描、调研、分析、事件、复盘、冲突和过期案例。验收指标为必需项召回率 100%、否决/冲突/否证/过期条件零遗漏、无未来信息回填；每个套件自行绑定会话身份并预注册载荷降幅、主上下文比例和峰值 token 上限，指标必须来自可复核 telemetry，缺失时保持失败并披露限制。

正式工作区的一次性切换、删除旧结构和恢复操作不由本仓库实现自动执行，须另行获得用户授权。

字段原子化迁移同样只允许在隔离副本中进行：旧文件级档案保留原文并生成可核对的字段 identity/version/source/supersedes 映射，缺失值标记“当时未记录”。本轮没有修改任何真实对象档案。payload GC 与 live retrieval 分离；未来若实现，只允许先 dry-run 并证明 referenced-safe，正式引用仍存在时不得删除。

## 12. 工作区升级

新工作区只生成当前 schema。既有工作区影子迁移时可以重排目录和补齐结构元数据，但历史报告、判断、证据和复盘的原子命题、信息快照、来源状态和未知项必须保持原义；旧记录缺失的新字段只标记“当时未记录”，不得用当前知识回填。迁移验收后运行时只保留当前 schema，新旧样本按历史审计标记分层统计。

`AGENTS.md` 收缩为薄启动协议；专用步骤由六个 skill 与工作区模板/schema 持有，`研究规则.md` 继续保存规范性研究规则。

## 13. 验收

在隔离副本和合成行情中前向测试：模糊请求不预测、过期证据处理、利好计价与追高拦截、低热度候选隔离、直接分析不越权、复盘双轴、元复盘自治边界、复盘后前瞻快照隔离、旧 schema 只读、新 skill 触发互斥。最后用一个真实只读任务验证来源流程，不写真实判断日志。

六个工作流分别评价路由隔离、发现与漏检、证据质量、风险与校准、验证完整性、策略真实改进；任何局部指标不得抵消系统级风险恶化。
