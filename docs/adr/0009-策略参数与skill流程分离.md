# 策略参数与 skill 流程分离

策略画像、结构参数和情境参数统一存入投研工作区的版本化策略库，skill 只定义选择、执行、复盘与权限检查流程。相比把权重和阈值写死在多个 skill 中，这一分离让 L2 自治可以在许可字段内调整策略而不改写流程护栏，也使正式、影子和退役版本能够共享证据簇并被独立审计。

## Consequences

- 每个策略版本必须声明适用范围、激活与失效条件、最大判断周期、指标权重、阈值范围、支持教训和证据簇。
- 策略输入先标记为否决项、主证据、确认项或背景项，仅在同一角色内部使用数值权重或动态阈值；否决项不得被综合分抵消。缺少样本的初始数值标记为设计先验，不宣称已验证。
- 每个版本使用独立 Markdown 文件，YAML 元数据保存机器可读字段，正文保存逻辑、证据、反例与回滚条件；`策略库/索引.md` 只镜像当前正式、影子与即将失效版本。
- 策略库冷启动使用“试运行版本”：可受限执行但不得宣称已市场验证，判断若对未校准参数敏感则最高只能进入低置信区间；对参数不敏感的稳健结论不机械限级。
- 后续正式版本的替代候选使用影子版本；试运行、正式、影子、受限和已退役版本均保留，分析引用具体版本，复盘不得事后替换。
- 修改 skill 结构、风险护栏或策略库字段权限属于 L3；修改获授权的参数值属于 L2。
