# 以资格模式隔离当前分析与历史审计

用户已明确授权本次 L3 变更：工作集资格/选择语义、任务契约 schema 与注册契约、`shared/context` 内部实现、A-share skills、模板、ADR/架构，以及直接相关的校验和测试。本 ADR 不改变风险优先、弃权、证据底线强度、投资输出或自动交易边界。

## Decision

保持 `assemble` / `hydrate` 两个公共入口，在 module 内编译 requirement 级资格策略并写入 stable reference。采用三种模式：当前前瞻 `prospective_current`、原快照重建 `historical_as_of`、元复盘 `calibration_window`。复盘不用统一过期策略：原判断按自己的 snapshot，过程证据按原 judgment cutoff，结果数据按 review cutoff。

判断有效状态由不可变原判断加后续追加记录派生；终局结果、时限、事件失效、终止、退役和显式替代都会影响当前资格，但不会物理删除历史。多版本只按 logical identity、version 和 `supersedes` 收敛，禁止用文件日期猜测替代。对象档案改为兼容的字段原子 schema，每个字段独立持有核实时间、有效期、状态、来源和替代关系。

所有被排除候选保留 audit-only reference。hydrate 重新解析 Markdown、核对定位与内容哈希，并重放编译策略；语义 adapter 命中的无效历史也只能进入 audited exclusion。

## Consequences

- scan、investigate、analyze 的注册契约声明当前模式；review 契约声明三条独立 cutoff；meta-review 契约声明校准窗口。
- analyze 契约确定性实例化当前对象字段、活跃判断链、正式 handoff 证据和精确策略版本。retired 永不进入当前分析；limited 只有契约对该用途显式允许时可用。
- 旧对象档案仍保留为审计历史。本轮不对真实工作区执行字段原子迁移；未来只能用隔离副本迁移、影子回放、人工验收后再另行申请正式切换。
- 本轮不实现 payload GC。未来 GC 只能先提供 dry-run 和 referenced-safe 证明，任何有正式引用的载荷都不得删除。
