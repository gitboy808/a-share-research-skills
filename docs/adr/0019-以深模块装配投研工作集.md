# 以深模块装配投研工作集

在运行清单与阶段上下文之间设置一个投研工作集装配 module，其 interface 只暴露 `assemble(运行清单, 任务证据清单)` 和 `hydrate(稳定引用集合)` 两类能力，分别返回工作集、覆盖、缺口与引用，以及被定位的原子研究单元和核验原文。字段权威映射、结构化与语义检索、去重、时效、冲突、来源定位、软预算和具体索引实现都留在 implementation 内，不散落到六个投研工作流；这增加了中央 module 的责任，但为调用方提供更高 leverage，并把检索错误和验证集中在一个 locality 中。

## Consequences

- 各 skill 只声明任务所需证据和消费装配结果，不直接编排低层搜索、过期过滤、去重或文件读取步骤。
- module 的 interface 同时作为测试 surface；测试通过输入运行清单和任务证据清单验证覆盖、引用、缺口、时效与失败行为，不穿透内部实现。
- 语义引擎、结构化索引、来源缓存和测试替身属于内部 seam；替换 adapter 不改变投研工作流 interface。
